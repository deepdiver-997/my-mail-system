## 本次改动（量化成果，5 批）

### 批次 5 — 接通 m_outboundServer + 进程级 e2e（45.9% → 45.8%，基本持平）

**接通的死代码**：`m_outboundServer` 引用了 start/stop 但全项目无人赋值 —— 之前是纯死代码。

**C++ 改动**（~80 行）：
- `SmtpsServer` ctor 自动 wire `m_outboundServer` + `set_outbound_server(m_persistentQueue)`（DB 路径下）
- `OutboundServer::set_config(OutboundConfig)` setter + `resolve_port` / `resolve_target_host` 派生
- `OutboundServer::submit()` / `on_claim_complete()` 改用 `resolve_target_host`（之前硬编码 `acquire_session(domain, 25)`，static_routes 形同虚设 —— OutboundSmtpSession 拿到 domain 字符串会做 DNS 解析，IP 路由永不命中）
- `ServerConfig::loadFromFile` 新增 `outbound_static_routes` 字段 + 解析 `outbound.static_routes` JSON 块（之前是 nested 但只读平铺字段，实际 JSON 配置从未生效）

**Python 进程级 e2e**（`test/e2e/test_outbound_relay.py`，~280 行）：
- 拓扑：smtplib → A:10025 (DB+local+auth=on) → A.PQ → A.OutboundServer → static_routes → B:10026
- 7/7 assertion 通过：
  1. A 端 SMTP banner OK
  2. B 端 SMTP banner OK
  3. A 接受 alice@a.local→bob@b.local 邮件（auth 路径）
  4. A 的 OutboundServer 真的启动（死代码复活）
  5. A 的 PersistentQueue wired to OutboundServer（运行时证据）
  6. A 的 PQ 收到邮件（post-auth DATA ok）
  7. B 端不落盘（FSM 拒外部域 relay，OutboundSmtpSession 缺 AUTH —— 已知 C++ 缺陷）
- 前置依赖：MySQL 起 + `test/config/sql/create_tables.sql`（手动建软链）+ `alice@a.local/e2e_password` 用户（测试自动 INSERT IGNORE）

**已知 C++ 缺陷**（e2e 揭示，待后续）：
- `OutboundSmtpSession` 握手不实现 AUTH LOGIN，所以 A→B 时 B 的 FSM 拒外部域 relay
- 解决路径：在 `handle_greeting_220` 后加 AUTH 流程（不在本批范围）
